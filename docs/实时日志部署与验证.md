# 实时日志

## 功能与边界

菜单：系统监控 → 管理后台 → 实时日志，位于缓存列表之后。页面与接口共用 `monitor:realtimeLog:list` 权限，不增加重复列表按钮权限。

当前版本查看收到请求的 **zero-admin 单实例**，支持两种采集来源，页面标题下显示当前来源。

**完整进程控制台模式**：配置 `zero.realtime-log.console-file` 后，读取启动器或IDEA保存的真实控制台文件。覆盖Logback、`System.out`、`System.err`、直接写入标准输出描述符的代码，以及JVM启动警告、GC等写到相同输出流的原生内容。原样传输文本，不脱敏、不补时间前缀、不补换行、不截断长行；同一Logback事件不会重复入队。按用户要求与控制台原文一致，敏感字段也可能原样出现，现有 `monitor:realtimeLog:list` 权限需要严格控制，文件应保存在受控目录，禁止通过静态资源路径暴露。

**Logback应用日志模式**：未配置完整控制台文件时，保持原有采集。root链路的DEBUG SQL、参数、INFO、WARN、ERROR及堆栈均纳入，沿用原级别，不额外过滤请求或Logger。仍保留凭证字段脱敏、单条截断和内存淘汰。此模式不覆盖绕过日志框架的输出，不能当作完整控制台。

两种模式均不修改原控制台和原INFO/ERROR滚动日志。不自动授权、不新增匿名接口。完整模式显示的是输出文本，不模拟终端的ANSI颜色、光标控制或进度条覆盖行为。写到独立GC文件、`hs_err_pid`文件或其它文件的原生日志不属于stdout/stderr；服务进程崩溃后本服务HTTP接口也会不可用，已采集内容仍保存在输出文件中。

日志产生级别统一通过 `application.yml`、`logback-spring.xml` 及外部配置管理。当前root和业务包默认INFO、Spring包WARN；`PackageProperties` 只维护包路径，不再向JVM写入默认DEBUG。需要临时调试可显式使用 `--logging.level.com.zero=DEBUG`；仅修改页面筛选不会改变服务输出级别。完整重启后新配置生效，旧进程内已写入的系统属性不会因热更新源码而自动清除；启动参数、环境变量或Nacos中的显式DEBUG配置仍需单独核对。

## 数据与容量

- `GET /monitor/realtimeLog/events`，使用现有 JWT、权限注解和接口谷歌验证链路，不新增匿名路径。
- 首次不传游标；后续传 `processId`、`after`，`limit` 最大500。响应为 `AjaxResult.data`，字段包含 `events/processId/nextCursor/hasMore/gap/reset/sourceMode`。
- 事件包含 `sequence/timestamp/level/thread/logger/text/truncated`。完整模式额外返回 `raw=true`，前端不得补换行；原文块级别统一为CONSOLE，不猜测日志严重程度，因此完整模式禁用级别筛选，保留关键字过滤。原始块的 `sequence/nextCursor` 是文件字节偏移；应用模式仍为事件序号。下次原样传递 `nextCursor`，不要自行计算。
- 应用模式保留5000条、10MB UTF-8文本预算，单条64KB；先到容量限制时淘汰旧事件，超长日志截断并标记。文本预算不等同于JVM实际堆占用。
- 完整模式首次最多回看10MB，单次最多读取512KB，每块默认64KB；长行分块传输后原样拼接，不丢弃单条超限部分。文件末尾只有半个多字节字符时等待后续字节，不生成乱码。文件替换或观察到截断时重置游标并通知页面。支持UTF-8以及按配置指定的GBK等文件编码，必须与写入端一致。
- 完整文件超过回看窗口时只显示最近内容并提示；日志仍在磁盘文件中。应用模式只在内存保存，进程重启后不保留。两种模式均不提供历史检索或文件下载。
- 页面每秒增量轮询，有积压时每100ms追赶；请求不重叠，网络或服务异常以2、4、8、16、30秒退避。登录失效、权限拒绝、取消安全验证或谷歌验证失败时停止，用户处理后可重新连接。
- 页面最多保留2000条/5MB，按纯文本分块渲染。关键字与级别筛选仅作用于当前保留内容，清空显示只清理本页，不删除服务端日志、不重置游标。
- 日志窗口按视口高度减330px自适应，出现提示条时额外预留20px（最小320px、最大1200px），为顶部工具区和底部说明留出空间。向上滚动或点击“回到顶部”停止自动跟随，新增日志不会把阅读位置拉回底部；点击“回到底部”跳到最新内容并恢复自动跟随。暂停、页面隐藏、路由离开及keep-alive停用时停止轮询，恢复后续读。日志接口不进入运行统计，避免每秒轮询制造统计记录；该请求链路实际输出的日志仍和控制台一样进入缓冲，不做静默过滤。

## 配置和上线

完整模式需要配置输出文件；未配置时使用兼容的应用日志模式。属性由 `logback-spring.xml` 读取，可通过环境或启动参数覆盖，修改后完整重启服务，不承诺Nacos动态刷新：

| 配置项 | 默认值 | 安全范围 |
| --- | --- | --- |
| `zero.realtime-log.console-file` | 空，应用模式 | 服务管理员指定的文件，HTTP不能传路径 |
| `zero.realtime-log.console-charset` | UTF-8 | 与文件实际编码一致 |
| `zero.realtime-log.max-events` | 5000 | 1～50000 |
| `zero.realtime-log.max-bytes` | 10485760 | 1024～104857600 |
| `zero.realtime-log.max-event-bytes` | 65536 | 512～1048576，且不超过总容量 |

对应环境变量为 `ZERO_REALTIME_LOG_CONSOLE_FILE`、`ZERO_REALTIME_LOG_CONSOLE_CHARSET`、`ZERO_REALTIME_LOG_MAX_EVENTS`、`ZERO_REALTIME_LOG_MAX_BYTES`、`ZERO_REALTIME_LOG_MAX_EVENT_BYTES`。完整模式的max-bytes是首次回看窗口，max-event-bytes是传输块大小，max-events不控制磁盘文件大小。如果运行环境替换了 `logging.config`，需要在实际生效配置中保留实时Appender、完整文件属性及root引用。

### IDEA 启动

1. 打开 `Run → Edit Configurations`，选择 `zero-admin`，通过 `Modify options` 开启 `Save console output to file`。填写当前机器上的独立绝对路径。下文示例使用 `D:/workspace/zero-admin/logs/zero-admin/console-idea.log`，已有同名文件时选择新路径。[JetBrains 设置说明](https://www.jetbrains.com/help/idea/setting-log-options.html)
2. VM options增加以下参数，文件路径必须与上一项完全一致，不能写成INFO或ERROR单独日志文件：

```text
-Dzero.realtime-log.console-file=D:/workspace/zero-admin/logs/zero-admin/console-idea.log
-Dzero.realtime-log.console-charset=UTF-8
-Dfile.encoding=UTF-8
-Dsun.stdout.encoding=UTF-8
-Dsun.stderr.encoding=UTF-8
```

3. 核对保存文件的实际编码。UTF-8 可以沿用示例，GBK 则将 `console-charset` 改为 GBK。完整停止后重新运行，页面应显示“完整进程控制台”。IDEA 写入文件时可能短暂缓冲。

### 独立启动器

`scripts/ConsoleLauncher.java` 使用Java17源码启动，无需新依赖。它将子进程stdout和stderr合并成一条流，每个字节同时写入终端与指定文件，并自动给子进程设置完整文件环境变量。UTF-8编码参数自动追加；子进程退出码向上传递，父进程正常退出时通知子进程结束。

先按现有流程打包，再从仓库根目录运行（jar名称按实际打包产物核对）：

```powershell
$consolePath = Join-Path (Get-Location) ('logs/zero-admin/console-' + [guid]::NewGuid().ToString() + '.log')
$javaExe = (Get-Command java).Source
java .\scripts\ConsoleLauncher.java $consolePath -- $javaExe -jar .\zero-admin\target\zero-admin-1.0.0.jar
```

Linux同样可以用 `java scripts/ConsoleLauncher.java <新的输出文件> -- java -jar <实际jar路径>`。原有VM参数放在子进程 `java` 后、`-jar` 前，Spring参数放在jar后；命令参数不经shell拼接，也不打印到日志。启动器不接管现有IDEA进程、不自动启动业务服务、不修改现有zero.bat/zero.sh。

输出文件必须是新文件，启动器拒绝覆盖已有文件。文件持续增长，不自动轮转或删除；部署环境应配置磁盘配额与留存策略，不能把原Logback的60天滚动策略当作该文件的清理策略。需要轮转时优先使用替换文件方式；同一文件在两次轮询之间截断后又增长超过旧长度的场景无法可靠识别，不建议使用copytruncate。两条独立流在合并前没有可恢复的全局时序；启动器终端和文件使用同一合并流，因此二者字节顺序一致。

IDEA启用DevTools时，Logback采集器可能由基础类加载器加载，Controller由RestartClassLoader加载。同名静态Buffer不是同一个实例。接口必须从实际root Appender的JDK Function入口读取，不可直接读取Controller侧的 `RealtimeLogBuffer.INSTANCE`。采集器缺失、未启动或仍为旧版本时，接口明确报错，不回退空缓冲。升级此次兼容修复后需要在IDEA完整停止并重新运行一次，不能只依赖DevTools热重启刷新已经加载在基础类加载器中的旧Appender。

### 上线验收

1. 发布后端和前端资源并重启 admin，检查原控制台与文件日志仍正常。
2. 实时日志菜单统一维护在初始化脚本 `sql/zero_admin.sql`，不再提供独立增量文件；菜单ID127、父目录121、排序8，不绑定普通角色。数据库操作尚未自动执行。
3. 已有数据库不会因初始化脚本修改而自动增加菜单；该脚本包含删表重建语句，禁止为补充菜单而直接整份执行。已有库需先核对菜单ID、路径、权限是否冲突，再经确认单独应用对应菜单定义。
4. 超级管理员重新登录加载菜单；普通角色经确认后按需授予此菜单权限，再重新登录。此功能不会自动授权任何普通角色。
5. 对照实际控制台检查 INFO、WARN、ERROR及异常堆栈，检查暂停恢复、切换菜单、断网恢复和重启提示。无需为了测试而修改生产日志级别或制造生产异常。

不支持跨进程聚合、跨重启历史、下载和日志级别修改。后续扩容多实例时，需增加实例路由或集中日志系统，不能把当前请求落到的实例当作整个集群。
