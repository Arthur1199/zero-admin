# 备忘录功能部署

## 入口与权限

- 归属zero-admin，数据表为管理库的sys_memo，不调用report。
- 入口为“系统工具 → 备忘录”，与“系统接口”同级并排在其下方。
- 页面组件：systemTools/memo/index；接口：/systemTools/memo。
- 菜单权限systemTools:memo:list包含列表及正文查看：普通账号可查看公开及本人私有记录；超级管理员可查看全部，包括他人私有记录。
- 新增、修改、删除分别需要add、edit、remove按钮权限，并同时要求菜单权限；普通账号仅维护本人记录，超级管理员可修改、删除全部记录。
- 超级管理员复用SecurityUtils.isAdmin(userId)判断，不以admin角色名称、全部按钮权限或客户端参数替代。服务端返回canManage控制页面操作资格，写入仍由服务端和SQL独立校验。
- 超级管理员修改他人记录时保留原创建人及创建审计字段，正文仍绑定原创建人ID加密；更新人记录实际操作账号，版本检查保持生效。
- 不自动给普通角色授权，不新增重复list/query按钮权限。

## 数据库脚本

备忘录表、菜单及新增、修改、删除按钮统一维护在 [zero_admin.sql](../sql/zero_admin.sql)。已有数据库需要另外核对当前结构和菜单，再由数据库管理员确认迁移方式。

备忘录菜单ID为129，父级系统工具ID为3，顺序为5，位于顺序为4的系统接口下方；按钮ID为1290、1291、1292，采用与其它初始化菜单一致的直接INSERT写法，不使用变量、动态父级查询或NOT EXISTS判断，不为普通角色添加授权。

sys_memo沿用初始化脚本的DROP TABLE IF EXISTS及CREATE TABLE方式，包含正文密文、可见范围、创建用户、并发版本和索引定义。整个初始化文件包含重建表操作，仅用于确认可以重建的新库，不应对已有业务数据直接执行。

保留version字段：每次修改递增，修改、删除必须带读取时的版本；冲突后提示刷新，避免多窗口覆盖或误删新内容。已取消手动展示顺序，前端、接口及初始化表中均无sort_num；列表统一按create_time倒序、memo_id倒序排列，新添加的记录靠前，同一时间创建时由ID保证稳定分页。索引分别包含创建用户/可见范围与创建时间、ID，并提供创建时间及ID的全局索引；标题和地址包含查询不能靠普通B树索引加速，数据量大时需按实际执行计划评估。

列表单页限制为1至500条，默认10条，不接受客户端orderByColumn覆盖固定排序；查询标题、地址分别限制200、2000个字符，可见范围只接受空值、0或1。无有效登录用户ID时拒绝读取或写入，并保留401响应码。

## 独立加密密钥

密钥在 `zero-admin` 启动时读取。当前主配置中的该项已有值且文件受 Git 跟踪。迁移到受控配置时，先安全备份原密钥，使用同一密钥验证已有正文可以解密，再重启各节点。不要直接以新密钥覆盖已有数据使用的密钥。

正文在应用层使用AES-256-GCM整体加密，保存格式为v1:Base64(12字节随机数+密文+128位认证标签)，创建用户ID作为附加认证数据。每次加密使用新随机数，损坏、错误密钥及未知格式均拒绝解密。

在部署环境的密钥管理中提供以下配置之一。代码读取 `zero.memo.encryption-key`，属性未解析到值时使用环境变量 `ZERO_MEMO_ENCRYPTION_KEY` 作为回退：

- 环境变量ZERO_MEMO_ENCRYPTION_KEY。
- 外部配置项zero.memo.encryption-key。

值必须为安全随机生成的32字节密钥的Base64编码，不复用JWT密钥。不要把密钥提交到仓库、存入sys_config或业务数据库、写进日志或反馈到聊天中；多节点必须使用相同密钥。

未配置或格式无效时，不影响原有服务启动，但新增、修改及正文查看会拒绝。密钥应独立备份；丢失后无法恢复正文。当前只支持一个有效密钥，不支持直接替换后自动读取旧密文，轮换须先单独设计迁移流程。

## 内容处理边界

- 列表不查询正文，详情校验可见范围后才解密；所有响应设置Cache-Control: no-store。
- 保存请求关闭通用sessionStorage防重复提交缓存，改由页面提交锁防止重复点击；正文不保存到浏览器持久化存储，弹窗关闭、路由停用或组件卸载时清理。
- 保存期间禁用表单输入。旧弹窗关闭动画不能清空已重开的新表单；页面离开后，迟到的列表、详情和保存结果不回写旧状态，未完成确认的保存或删除不再提交；已发出的写请求不承诺撤销。缓存页面再次激活时重新查询元数据。
- 操作审计保留操作类型及操作人，但关闭请求参数和响应记录；业务校验错误不回显输入，接口异常不输出原始正文、SQL或解析堆栈。
- 正文按纯文本展示，不使用v-html；输入中的换行、空格及特殊字符原样保留。标题、地址、备注为普通明文元数据，不应填写密码或Token。
- 公开保存时再次提示完整内容对菜单权限用户可见；普通账号不会因此获得他人记录修改、删除权。私有表单提示超级管理员仍可查看和维护。
- 删除实际移除记录，不提供回收站；已有数据库备份中的历史密文按部署备份策略管理。
- 生产链路须使用HTTPS，并检查网关/APM是否额外采集请求正文；应用层保护不能替代外围访问及日志配置。
