# 管理后台运行统计

## 初始化与开关

所有统计表、菜单及后台参数统一维护在 `sql/zero_admin.sql`，不再单独提供增量或迁移脚本。本次未对实际项目数据库执行初始化。该文件包含原项目的DROP及重建语句，只用于确认需要初始化的测试库，不应用于保留数据的库。

8张统计表均按现有初始化风格先DROP TABLE IF EXISTS、再CREATE TABLE，重新执行会清空统计数据。初始化还包含只读菜单，以及以下系统内置参数（config_type=Y，参数ID=13）：

| 参数名称 | 参数键名 | 初始化值 |
| --- | --- | --- |
| 是否开启后台运行统计 | sys.statistics.enabled | true |

在“系统管理 → 后台参数设置”中修改参数值：true开启；false关闭；缺失、空值或非法值按关闭处理。允许true前后空格及大小写，不把1、yes当成开启。修改通过原参数Service同步Redis缓存，下一次请求和后台任务读取新值，无须重启。关闭前已进入采集的请求以及已开始的消费轮次允许完成；关闭期间暂停新请求采集、后续消费及在线采样，不删除历史数据或持久化队列，再次开启后继续消费。

旧的 `zero.statistics.enabled` 不再被读取，不必配置在本地或Nacos中。初次部署修改Java代码仍需正常重启服务；后续仅修改后台参数不需重启。如果直接用SQL修改sys_config，应通过后台参数页“刷新缓存”同步；本次不执行刷新缓存操作。

参数读取复用ISysConfigService。Redis读取异常时，统计开关独立回退查询MySQL；两者均不可用时保留本实例最近有效值，首次读取即失败则默认关闭。页面的switchAvailable=false明确显示读取故障，不能把存储异常解释为管理员关闭。此兜底不修改原参数业务，也不输出参数内容或连接异常正文。

菜单为“系统监控 → 管理后台 → 运行统计”，路径/monitor/admin/statistics，组件monitor/statistics/index，权限monitor:statistics:list。普通角色不默认授权，不复用在线用户会话凭证查询权限。菜单ID=126，父级为初始化文件中已存在的管理后台目录ID=121；与其它菜单一致，直接使用INSERT ... VALUES初始化。参数同样直接写在原sys_config初始化数据后，不使用条件查询插入。

## 其它采集参数

队列、阈值、调度和排除规则仍使用zero.statistics配置前缀，可以在实际加载的本地配置或Nacos中按需覆盖；以下示例没有总开关，默认值通常无需重复配置。

```yaml
zero:
  statistics:
    stream-key: zero:admin:statistics:events
    group: admin-statistics
    slow-millis: 1000
    batch-size: 500
    poll-millis: 5000
    claim-idle-millis: 60000
    sample-millis: 30000
```

多实例共用数据库、Stream键和消费组，不同环境使用不同Stream键。调度间隔在启动时读取，修改后重启admin。excludes覆盖默认排除列表时，应保留基础设施路径；统计接口和OPTIONS始终排除。当前resources/localYml导入被注释，文件仅放入该目录不代表自动生效。

## 指标口径

- 按Asia/Shanghai归属请求完成日期。耗时由单调时钟计算，微秒保存、毫秒展示，包含认证、业务、数据库及下游调用，不包含统计事件投递，不等于浏览器网络往返。
- 包含admin自身及其report/file代理；直接访问下游不计。重试及二次验证码重发各算一个HTTP请求。
- 默认排除静态资源、文档、Actuator、Druid、OPTIONS及统计查询。未进入MVC的安全拒绝和未知URL归入固定类别，避免任意路径造成维度膨胀；MVC接口按HTTP方式和映射模板归类，不存实际路径参数。
- 统一JSON以HTTP2xx且code=200为成功，业务码500不直接视为系统异常。认证/权限拒绝、业务拒绝、系统异常、其他HTTP失败及未知分别累计；JSON缺少code为未知。文件输出按HTTP及异常判断，不保证客户端完整保存。
- 成功登录须登录服务最终返回且响应成功。登录失败不计认证用户活动，退出不计登录次数。不存密码、验证码、Token、IP、请求参数或响应正文。安全链直接输出JSON时仅临时观察最多2048字节前缀提取code，随后释放，不落日志或数据库。
- 在线人数按有效会话用户ID去重，会话数保留多端。页面关闭但会话未过期仍可在线。近5分钟活跃包含后台轮询，不代表人工操作。
- 在线每30秒SCAN采样，跳过失效缓存，不续期、不还原Token。跨实例租约控制采样；分钟保存最新值及采样峰值，趋势显示均值与采样峰值，缺口不补0。辅助活跃索引失败不阻止主统计ACK，并标记在线采样不可用。
- 查询最多366天，7天以内按分钟、超过7天按日；登录趋势按日。平均耗时由总耗时/次数计算，包含失败。慢接口排行默认至少10次调用，分页最大100条，排序使用固定白名单。
- 首个请求分钟不等于启动时刻；历史空缺不等于实际零调用。无请求时成功率和平均耗时为空。分页停留在当前阅读位置，不自动回顶。

## 持久化与恢复

请求完成后使用唯一事件ID同步写Redis Stream；Redis失败或结果不确定时以同一ID同步写MySQL回退表，不能先进入内存队列再持久化。

消费者每轮最多读取500条新消息，接管超过60秒未确认的pending，并独立读取MySQL回退队列。按事件独立事务登记唯一ID、累计各维度、完成回退状态，提交后才ACK。重复投递、接管和双通道到达不会重复累计。不宣称整批原子提交或无限吞吐；坏事件保留待处理，不静默丢弃。后台执行器独立管理，不新增业务@Scheduled或Quartz数据库任务。

MySQL不可用不ACK；Redis不可用仍可消费MySQL回退事件，开关也可回退MySQL读取。保证admin重启后已持久化事件恢复，不保证尚未完成或尚未持久化的请求。两种存储同时不可用时业务优先，统计可能有缺口；内存缺口数及故障状态仅代表当前实例，不能证明历史或其他实例无故障。

Redis需独立可靠部署，建议AOF及持久卷，避免队列键过期或被淘汰。本次不修改生产Redis/MySQL配置，不验收断电、丢盘及主从切换。同步投递可能增加请求结束等待，超时沿用实际连接配置。不要随意修改生产Stream键或消费组；重启后pending可能等待接管阈值才恢复。

## 容量与清理

不自动删除或裁剪Stream、回退事件、去重记录和统计表。ACK不删除Stream正文，应监控Redis内存、Stream长度、pending、lag及MySQL增长。长期运行前需确认清理窗口，不能无限保留。

建议后续经确认再实施分钟90天、日1年清理；事件及去重清理必须同时考虑pending、回退和重放窗口，不能只按日期删除去重记录。实际数据库初始化、普通角色授权及数据清理均需单独确认。

## 验证

后端StatisticsSwitchTest验证原参数Service缓存更新、非法值关闭、读取故障兜底及旧YAML无效；StatisticsCaptureTest、StatisticsWebTest、StatisticsPersistenceTest覆盖采集、业务码、权限、事务回滚、双通道回退、真实Stream接管与在线采样。持久化用例从统一初始化SQL提取统计片段和依赖表结构，不执行整个重建脚本。

持久化测试仅允许显式指定本机zero_stat_test或zero_stat_test_后缀测试库，使用root空密码隔离容器，不读取业务数据库配置。Redis端口默认13379，可由ZERO_STAT_TEST_REDIS_PORT覆盖。

```powershell
$env:ZERO_STAT_TEST_MYSQL_URL='jdbc:mysql://127.0.0.1:13316/zero_stat_test?useSSL=false&serverTimezone=Asia/Shanghai&characterEncoding=UTF-8'
mvn -pl zero-admin -am test '-Dtest=StatisticsSwitchTest,StatisticsCaptureTest,StatisticsWebTest,StatisticsPersistenceTest,OnlineAuthorizationTokenTest' '-Dsurefire.failIfNoSpecifiedTests=false'
```
