## 2. 构建准备

使用Node24.21.0、npm11和提交的package-lock.json。`.nvmrc`只声明版本，不自动修改用户的全局Node安装。

在仓库根目录执行：

```powershell
node --version
npm --version
cd zero-ui
npm ci
npm run check:migration
npm test
npm run build:prod
```

staging 使用 `npm run build:stage`。两个构建命令都写入 `dist`，发布前核对最后一次构建所用环境与 API 前缀。详见[前端项目说明](../zero-ui/README.md#发布)。

## 3. 发布门槛

- 静态检查、单元测试、生产/staging构建和三内核自动化全部通过。
- 在目标环境验证真实登录、权限、上传、admin 对 report/file 的代理，以及实际浏览器表现。
- 验证代码生成时，记录真实单表、树表和主子表的覆盖范围。隔离模板渲染和模拟接口结果在专项报告中单独记录。
- 保存并比较原入口/JS/CSS体积，检查新增大包是否影响首屏；不提高警告阈值掩盖问题。
- 发布生产配置、部署静态产物或执行真实删除/权限操作之前，按项目规则取得确认。

## 4. 静态部署检查

输出目录仍为dist，资源仍在static，根路径部署。继续使用现有Java服务和接口前缀，不增加新的跨域或服务直连方式。

- 对非API前端路由回退index.html，刷新深层菜单和复制URL均能进入。
- `/prod-api`仍代理admin；报告/文件请求仍经admin入口，不直接请求report/file端口。
- 发布整个新产物，避免旧HTML与新hash资源混用。
- index.html不长期缓存；hash静态文件可长期缓存。
- gzip副本和原文件同时发布，核对Content-Encoding及回退行为。
- 使用生产测试账号冒烟，确认Token、登录超时、谷歌验证、菜单、表格、下载、主题和上传。

本轮未修改实际Nginx、生产配置或部署服务器，上述为执行步骤而非已完成验证。

## 5. 回退

出现登录、权限、关键维护、上传或路由阻断时，暂停扩大上线，切回发布前保存的**完整静态产物**；同步恢复对应HTML/资源版本及缓存，重新验证登录和关键页面。

仅回退前端静态产物时，保留原浏览器令牌、布局与主题设置。若同批发布了后端模板、SpringDoc 或安全配置，先核对前后端是否兼容，再按对应后端发布记录处理回退。

源码回退在独立目录或隔离分支使用备份/对应Git版本恢复，保留本次差异及用户后续改动。不要在当前工作区使用`git reset --hard`覆盖其它工作。
